# EdgeDesk Phase 1 — Engineering Baseline

Status: **scaffold implemented; platform integration requires environment validation**.

## Phase 1 is deliberately minimal

Implemented: C++17 core, libhv HTTP entry, `GET /api/health`, React+TS+Vite skeleton, reusable SVG/token references, disk and GCC15 `#embed` asset providers, CMake presets, generator/core unit tests, smoke script.

Not implemented: authentication, file management, PTY/Bash/WebSocket session management, monitoring, real floating windows, multi-user, TLS, public binding, and physical ARM device validation. Frontend labels deliberately show "尚未实现" rather than fake device metrics.

## Prerequisites

- Native development: CMake >=3.24, Ninja, Python3, Node.js and npm, C++17 compiler, git/HTTPS access on first libhv download.
- Release embed: GCC 15+ compatible with target ABI, musl static toolchain if fully static Linux is required. CMake and npm run on the **host**, not the device.
- No automatic OpenHarmony target is claimed. ARM32/ARM64 require their respective GCC15+ musl toolchains; compile and runtime compatibility need verification separately.
- libhv is pinned to commit `71770e04becaa149e0ef8ffc4d3900c5466ddddb` (tag v1.3.4). On an offline builder, pass `-DFETCHCONTENT_SOURCE_DIR_LIBHV=/opt/vendor/libhv` pointing to that checked-out source.

## Build and run

```sh
# Frontend (first install creates package-lock.json; commit this lockfile afterward)
cd web && npm install && npm run build && cd ..

# GCC 15+ release: frontend bundles into generated #embed arrays
cmake --preset release-embed
cmake --build --preset release-embed
./out/build/release-embed/bin/edgedesk --port 8080

# Development on an older compiler: serve web/dist from disk
cmake --preset dev-disk
cmake --build --preset dev-disk
./out/build/dev-disk/bin/edgedesk --port 8080 --web-root web/dist

# Open browser http://127.0.0.1:8080 ; verify API
curl -i http://127.0.0.1:8080/api/health
bash scripts/smoke.sh out/build/dev-disk/bin/edgedesk 19091 web/dist
```

**Note on package lock:** Due to offline initial bootstrap the repository does not ship a verified npm lockfile. Once npm has network access, run `cd web && npm install`, verify `npm run build`, then commit the generated `web/package-lock.json` before CI uses `npm ci`. CMake currently runs `npm install` to permit this initial bootstrap; switch to `npm ci` after committing the lockfile.

### Native core checks without npm, libhv, or GCC 15

```sh
cmake --preset host-offline-tests
cmake --build --preset host-offline-tests
ctest --preset host-offline-tests
```

These validate only the C++ core and Python `#embed` generator; **they do not validate libhv serving or GCC15 compiling**.

## Deployment boundaries

- Phase 1 refuses non-loopback `--host`; it has no login, TLS, or privileged endpoints. Do **not** relax this prior to accepted auth design.
- `--web-root` is only meaningful in disk mode; override its source-tree default when copying binary and frontend files to a new location.
- Web static assets never access device filesystem APIs. The "file management" module is future work.
- Embedded file registry is generated by `tools/gen_embed.py` into `out/build/<preset>/generated`; do not commit it.
- React `web/dist` is ignored; only final output gets embedded. Vite base is `/`; subpath deployment is not supported until separately designed.
