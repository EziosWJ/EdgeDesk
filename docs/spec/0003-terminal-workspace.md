# SPEC-0003：Bash 终端、多 Tab 与浮动窗口

- 状态：**Baseline（核心行为已确认）**
- 日期：2026-10-16
- 关联：[架构与安全](../adr/0002-architecture-security.md)

## 终端运行环境（已确认）

- 终端必须连接真实的 **Bash**，而非仅启动 `/bin/sh` 的简化命令执行器。
- 必须支持 Bash 交互式/登录环境以及相关环境变量和 profile 配置。
- 推荐使用 `forkpty` 等 POSIX PTY 机制创建交互式登录 Bash，实际参数和 Bash 路径需根据设备验证。
- Bash 登录时可加载 `/etc/profile` 及用户的首个适用登录配置文件（如 `~/.bash_profile`、`~/.bash_login`、`~/.profile`）；**`~/.bashrc` 并非登录 Bash 必然自动加载**，若需加载应由配置显式衔接，避免错误假设。
- 如果目标设备未安装 Bash，不得默默退化为 `sh` 并声称符合此需求；兼容策略待确认。

## 交互能力（已确认）

- 使用 WebSocket 进行终端输入/输出数据交互，PTY 负责真实 Shell。
- 支持浏览器尺寸变化同步终端窗口大小（`TIOCSWINSZ` / `SIGWINCH`）。
- 可在文件管理页面从当前目录启动终端。
- 多个终端 Tab 对应独立后端 Bash/PTY 会话。

## 会话保持行为（已确认）

| 用户操作 | 后端 Bash / PTY 是否继续运行 | 页面行为 |
| --- | --- | --- |
| 从终端 A 切到终端 B Tab | 必须继续 | 继续显示/恢复对应会话 |
| 导航到其他页面 | 必须继续 | 返回时可关联原有会话 |
| 浏览器刷新页面 | 必须继续 | 刷新后可重新连接原有会话 |
| 浏览器彻底关闭 | 继续运行至空闲超时（见 ADR-0005） | 不在 V1.0 会话保持承诺内，等同断线处理 |
| 显式关闭终端 Tab | 销毁会话（HTTP close 或 WS `close`） | 关闭视图并终止对应会话 |
| 进程退出或设备重启 | 不保证保持 | 不在 V1.0 会话保持承诺内 |

注意：**WebSocket 断连不是 PTY 会话退出信号**。刷新/导航应在有限时间内允许安全重连；会话需要归属校验，不能仅凭可猜测 ID 抢占他人终端。

## 文件管理页面浮动工作区（已确认）

- 支持多个窗口同时打开，窗口类型至少包括 Bash 终端与文本编辑器。
- 每个窗口支持拖拽、缩放，可覆盖主文件管理界面。
- 窗口视图的销毁和后端终端会话销毁必须解耦。
- 窗口最小化、层级置顶、跨刷新窗口位置恢复尚待确认，不应默认视为已确认功能。

## 建议技术设计（待实施验证）

- 后端由 `TerminalSessionManager` 管理会话 ID、PTY FD、子进程、权限、连接关系、重连和超时。
- 终端前端候选为 xterm.js；应用级 UI 框架 React 仍待最终确认。
- 为无客户端连接期间的 PTY 输出设置**有界缓存**，并配置资源限额，避免输出过快耗尽设备内存。
- 限制并发终端数、空闲时间、进程权限；正确处理会话回收、Shell 退出和服务关闭。
- `POST /terminal/exec` 如保留则默认禁用；CmdGuard 黑名单仅用于误操作提示，不能代替权限边界。

## 验收

1. 两个独立 Tab 中分别运行持续输出命令，切换 Tab 不终止任一进程。
2. 页面导航及浏览器刷新之后，重新连接原会话，命令仍在运行。
3. Bash 的登录环境和配置加载在目标设备上验证通过。
4. 文件管理页面同时打开两个终端和两个编辑器，窗口均可独立移动与缩放。
5. 断线、异常退出和会话上限场景没有 FD、PTY 或子进程泄漏。
