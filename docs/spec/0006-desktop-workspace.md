# SPEC-0006：桌面工作区与应用窗口管理

- 状态：**Approved（产品决策已确认，尚未实施）**
- 目标版本：V1.2
- 日期：2026-10-18
- 前置基线：[SPEC-0001 产品范围](0001-product-scope.md)、[SPEC-0002 文件管理](0002-file-management.md)、[SPEC-0003 终端工作区](0003-terminal-workspace.md)、[SPEC-0004 设备仪表盘](0004-device-dashboard.md)、[SPEC-0005 认证与设置](0005-authentication-and-settings.md)
- 技术决策：[ADR-0009 桌面架构](../adr/0009-desktop-workspace-architecture.md)、[ADR-0010 桌面状态与会话恢复](../adr/0010-desktop-persistence-and-recovery.md)

## 1. 目标与定位

EdgeDesk V1.2 从以页面切换为主的 Web 运维工作台，演进为以桌面为入口、以应用窗口为交互单位的轻量运维桌面。登录成功后进入桌面；设备概览、文件管理、终端和系统设置作为应用窗口运行。桌面层统一管理应用入口、窗口生命周期和本地布局。

本版本主要改造 React 前端。继续使用现有 C++17/libhv 后端、认证与授权机制、REST/WebSocket 协议、文件服务、真实 Bash PTY、指标采集、无数据库和单二进制发布方案。不为桌面布局增加服务端数据库，不引入 Electron/Tauri，也不引入完整桌面框架。

## 2. 已确认的产品决策

1. 使用完整桌面模式；认证成功后显示桌面，不再使用传统侧边菜单作为主导航。
2. 应用默认以普通浮动窗口打开；窗口可拖动、缩放、置顶、最小化、最大化、还原和关闭。
3. 设备概览是独立、可拖动和缩放的窗口。
4. 文件管理支持多个实例；每个窗口拥有独立目录上下文。
5. 终端窗口关闭仅关闭/分离窗口界面，不终止 Bash；仍存在的会话可重新连接。显式结束会话与关闭窗口是不同操作。
6. 桌面图标支持拖拽排列、单击选中、双击启动。
7. Dock 使用底部居中悬浮布局；显示固定应用、运行状态和最小化窗口恢复入口。
8. 应用启动器提供应用网格、搜索和简短应用说明。
9. 实现基础窗口与菜单快捷键；不得抢占浏览器保留快捷键。
10. 桌面布局、窗口几何状态保存在当前浏览器本地；刷新后恢复完整工作区。
11. 恢复时自动尝试重新连接仍存在的终端会话；会话不存在时显示明确的结束/不可恢复状态，不伪造原会话。
12. 编辑器采用显式保存；关闭未保存内容时提醒。不在 V1.2 自动持久化文件正文草稿。
13. 窗口拖拽与缩放继续使用自研实现并完善，不引入 react-rnd 等替代组件。
14. 桌面优先；窄屏时应用窗口自动最大化，保留核心操作。
15. V1.2 只实现核心桌面，不包含窗口分屏和多工作区。

## 3. 应用与窗口模型

### 3.1 应用注册

所有可从桌面、Dock 或启动器打开的应用必须通过统一 AppRegistry 注册。应用描述至少包括稳定的 appId、显示名称、图标、简短说明、启动入口、实例策略和窗口默认尺寸。桌面 UI 不应为每个应用单独编写启动分支。

首期注册应用：

| appId | 应用 | 实例规则 | 行为 |
| --- | --- | --- | --- |
| dashboard | 设备概览 | 单实例 | 显示现有 CPU、内存、磁盘、网络指标和实时曲线；关闭窗口不停止全局采集连接 |
| files | 文件管理 | 多实例 | 每个窗口独立目录上下文；从目录打开终端时将该目录作为工作目录 |
| terminal | 终端工作区 | 多实例 | 保留现有多 Tab、独立 Bash 会话、会话刷新/导航恢复能力；可从文件管理打开指定 cwd 的独立终端窗口 |
| settings | 系统设置 | 单实例 | 保留现有认证状态、修改密码、系统信息和偏好设置能力 |

文本编辑器和文件预览继续作为窗口类型/内部工具注册，不要求在桌面图标中单独显示。打开同一文件时沿用现有行为；如现有窗口已打开，应优先聚焦已有实例，除非既有行为明确要求新建实例。

### 3.2 统一窗口管理

窗口管理器负责创建、关闭、聚焦、层级调整、移动、缩放、最小化、最大化和还原。业务应用不直接修改其他窗口状态，也不自行分配 z-index。

- 默认以普通浮动窗口打开；新窗口初始位置应错开，避免完全重叠。
- 点击窗口内容或标题栏使其获得焦点并置于最前；焦点变化应有可见反馈。
- 拖动窗口时标题栏可拖动，窗口操作按钮、输入框、终端区域和其他交互控件不能意外触发拖动。
- 缩放和拖动必须约束在可视视口内；窗口至少保留可操作的标题栏区域可见。
- 最大化窗口占用可用应用区域，不能覆盖认证 UI，也不能造成页面横向滚动。
- 最小化只隐藏窗口视觉层，不卸载业务组件、不清空编辑器内存状态，也不应仅因窗口隐藏而关闭终端 WebSocket。真正关闭窗口时才卸载 UI。
- Dock 中的最小化项可恢复原窗口；恢复后保留此前几何状态。
- 关闭窗口与终止后端会话必须分离。终端窗口关闭只分离界面；显式结束会话仍按终端现有操作和 SPEC-0003 执行。
- z-index 应在长时间连续聚焦后保持有界且顺序正确，避免无限增长导致层级异常。
- 应用单实例规则由 AppRegistry/WindowManager 统一执行；多实例应用必须具有稳定且独立的实例标识。

### 3.3 现有终端行为兼容

桌面化不得删除终端工作区已有的多 Tab、每 Tab 独立 Bash/PT​​Y、终端尺寸同步、刷新/导航重连、会话列表和从文件目录启动终端的能力。终端窗口/标签页是 UI 容器，后端 TerminalSession 是独立对象。关闭窗口不等于显式关闭某个 Tab；只有用户执行明确的结束会话操作时才终止会话。恢复流程必须根据后端真实会话列表进行关联。

## 4. 桌面交互

### 4.1 桌面图标

- 默认显示设备概览、文件管理、终端三个常用应用；系统设置通过启动器访问。图标及名称来自 AppRegistry。
- 单击只选中图标；双击启动应用。应提供键盘焦点和可见选中态。
- 图标可以拖拽排列，布局保存在浏览器本地；位置需在桌面有效区域内。
- 桌面图标与应用内部文件操作等工具按钮严格区分；不将所有业务操作变成桌面图标。

### 4.2 Dock

- Dock 固定在视口底部居中悬浮，不参与应用窗口的 z-index 排序，不得被普通窗口遮挡。
- 显示固定应用入口、运行中应用指示和最小化窗口恢复入口。
- 点击固定应用图标按 AppRegistry 规则启动或聚焦应用；多窗口应用需要提供窗口选择方式，不能任意聚焦不可预测的实例。
- Dock 不得遮挡应用关键操作；窄屏时可以缩小间距、允许横向滚动或采用适配布局。

### 4.3 应用启动器

- 从 Dock 的启动器入口打开，显示注册应用的图标、名称和简短说明。
- 支持按名称搜索；搜索无结果时显示明确空状态。
- 启动器关闭后焦点返回原来的可操作区域。Escape 可关闭启动器和非破坏性菜单。
- 不提供安装第三方应用或动态下载代码的能力。

### 4.4 快捷键

- 提供基础窗口最大化/还原、窗口切换、启动器/菜单关闭等快捷操作。
- 具体按键映射在实现阶段选择并记录在 UI 帮助/设计文档中；不得拦截浏览器刷新、地址栏、浏览器标签切换等保留组合。
- 当焦点位于 input、textarea、文本编辑器或终端中时，不得抢占会破坏文本输入或终端操作的快捷键。
- 快捷键操作必须复用 WindowManager 命令，不能形成第二套独立窗口状态逻辑。

## 5. 桌面状态持久化与恢复

### 5.1 存储边界

- 使用当前浏览器的 localStorage 保存桌面 UI 状态；不增加后端接口、数据库或跨浏览器同步。
- 使用独立、带 schema 版本的键，例如 edgedesk.desktop.layout.v1；解析和写入通过 DesktopPersistence 模块集中管理。
- 可持久化字段包括桌面图标位置、Dock 固定应用、打开窗口描述、窗口位置/尺寸/最大化或最小化状态、窗口顺序，以及重新连接所需的非凭据会话标识。
- 不得保存密码、认证 Cookie、API Token、文件正文或其他凭据。不得将服务端设置文件与桌面布局混为一体。
- 主题和现有跨浏览器应用偏好继续走当前 settings API；文件视图等现有设置行为不得被桌面本地状态覆盖。
- localStorage 不可用、空间不足、JSON 损坏或版本不兼容时，使用安全默认桌面启动，并显示非阻塞提示；不能阻止登录或损坏后端数据。

### 5.2 恢复顺序

1. 完成认证校验并进入已认证状态。
2. 加载当前服务端偏好和可用的终端会话列表。
3. 读取并验证桌面布局版本、应用 ID、实例 ID、窗口状态和几何值。
4. 先恢复桌面图标和 Dock，再恢复窗口描述；窗口坐标按当前视口重新约束，重复的单实例应用去重。
5. 文件窗口恢复前重新验证目录路径可访问；无法访问时打开明确错误状态，不得悄悄改到其他目录。
6. 终端恢复时按真实 session ID 查询/关联现有会话；存在则重新连接，不存在则保留窗口并显示会话已结束/不可恢复状态，不自动创建替代会话。
7. 编辑器重新读取磁盘文件。V1.2 不恢复文件正文草稿；外部修改或文件消失时提示用户，禁止静默覆盖。
8. 恢复完成后允许用户继续操作；单个窗口恢复失败不得导致整个桌面启动失败。

### 5.3 写入时机与兼容

- 窗口移动/缩放可以节流写入；窗口打开、关闭、状态变化、图标位置变化和 Dock 配置变化后必须最终持久化。
- 写入失败不应阻塞拖拽和窗口交互；页面退出前不得依赖异步写入保证数据安全。
- 状态 schema 升级必须有明确迁移或回退策略。未知 appId、无效几何值和损坏的单个窗口记录应被丢弃或安全降级。
- 登出时清理运行期内存状态和当前认证会话；是否保留非敏感桌面布局由持久化策略决定，不能清理或保存认证凭据。重新登录时仍需重新验证终端会话。

## 6. 响应式与可访问性

- 以桌面浏览器为优先目标。窄屏时应用窗口自动最大化，关闭自由拖拽/缩放操作但保留窗口切换、关闭、最小化或返回桌面的可用入口。
- 具体窄屏断点在实现阶段基于实际布局确定，初始建议 768 CSS px；不得将此值作为不可调整的业务协议。
- 支持鼠标和键盘操作，交互控件有可访问名称、可见焦点和合理的 tab 顺序。
- 主题继续遵循现有深色/浅色/跟随系统设置与设计 token；桌面层不能引入硬编码配色破坏浅色主题。

## 7. 非目标

- 不实现窗口分屏、吸附布局或多工作区/虚拟桌面。
- 不实现远程图形桌面串流、Electron/Tauri 外壳、应用商店、动态插件代码执行、多用户桌面或云端布局同步。
- 不重写文件服务、终端 PTY、指标采集、认证/授权、审计或部署配置。
- 不增加数据库、ORM、服务端桌面布局 API 或新的运行时依赖。
- 不自动保存编辑器文件正文到 localStorage。

## 8. 兼容性与安全约束

- 所有受保护 API 和 WebSocket 继续使用现有认证、Origin/CSRF/CSWSH 校验和限流；桌面化不能新增绕过认证的接口。
- 浏览器本地布局不是授权依据。恢复任何文件路径或终端会话前，必须由服务端现有授权机制验证请求。
- 不将终端 session ID 当作秘密凭据；服务端必须继续校验会话归属和授权，不得仅凭可猜测 ID 允许接管会话。
- 保留现有文件路径沙箱、原子保存、上传/下载限制和终端资源上限。
- 保留 React + TypeScript + Vite、xterm.js、Lucide、VS Code Icons、C++17/libhv、GCC 15+、musl 静态发布和 GCC #embed 资源模式。

## 9. 验收标准

### 功能验收

1. 认证流程不变；认证成功后进入桌面，登出后回到登录页，未认证用户不能访问桌面业务数据。
2. 桌面图标支持单击选中、双击启动和拖拽排列，刷新后位置恢复。
3. Dock 固定入口、运行指示、最小化恢复和多窗口选择行为符合本规范。
4. 启动器可列出已注册应用、按名称搜索并显示应用说明；空结果和关闭行为正确。
5. 设备概览、文件管理、终端、设置均为窗口应用；设备概览和设置遵守单实例规则，文件管理支持不同目录多实例。
6. 窗口移动、缩放、置顶、最小化、最大化、还原、关闭和边界约束正常；最小化不会卸载应用组件。
7. 文件管理原有目录树、列表/网格、上传、下载、编辑、重命名、删除、路径沙箱和从当前目录打开终端功能均保留。
8. 终端原有多 Tab、独立会话、Bash 登录环境、终端尺寸同步、断线/刷新重连和显式结束会话能力均保留。
9. 关闭终端窗口不会杀掉 Bash；刷新后可重连仍存在的会话；已结束会话显示真实状态，不创建假替代会话。
10. 编辑器最小化后保留未保存内存内容；关闭未保存文件时提示；V1.2 不持久化文件正文草稿。
11. 刷新后恢复完整工作区；坐标适配当前视口；无效路径、过期会话和单个窗口恢复错误不影响其他窗口。
12. localStorage 损坏、不可用或 schema 不兼容时，桌面使用安全默认值启动。
13. 窄屏时应用窗口自动最大化，主要操作可用，无页面横向溢出。
14. 基础快捷键可用且不会破坏终端/编辑器输入或抢占浏览器保留快捷键。

### 自动化与交付验收

- 新增覆盖 AppRegistry、单/多实例规则、窗口状态迁移、布局序列化/反序列化、版本不兼容、损坏数据、几何约束和恢复失败隔离的前端单元测试。
- 新增关键桌面流程集成测试：应用启动、多个文件窗口、最小化恢复、刷新恢复、终端会话重连与过期会话。
- 每个实现 Issue 至少附上相关测试结果；最终 PR 执行 scripts/test-pr.sh。纯文档变更可执行链接/Markdown 检查。
- 浏览器人工目视验收必须记录视口尺寸、检查步骤和实际结果；不得用代码审查代替目视验收，也不得将未验证的平台标记为通过。
- 更新 docs/README.md、相关 SPEC/ADR、设计说明及必要的测试文档；不得在本规范批准时宣称功能已实现。
