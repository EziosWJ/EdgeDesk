# SPEC-0005：管理员认证与系统设置

- 状态：**Baseline（V1.1 产品范围已确认；实现待完成）**
- 日期：2026-10-17
- 关联：[ADR-0008](../adr/0008-authentication-and-settings.md)、[V1.0 产品范围](0001-product-scope.md)、[API 契约](../api.md)

> 本文定义 V1.1 的目标行为，不代表功能已经上线。认证实现完成前，V1.0 的运行行为以现有 API 文档和测试结果为准。

## 1. 目标

将 EdgeDesk 的浏览器认证从 V1.0 的 Token 登录交换调整为单管理员密码认证；新安装首次进入初始化流程；管理员可以在设置页修改密码并查看系统信息。保留独立、可选的 Bearer Token 供脚本使用。继续保持单二进制、无数据库、适用于嵌入式 Linux 的部署方式。

## 2. V1.1 范围

### 必须实现（P0）

- 首次初始化页面及初始化状态检测。
- 高熵一次性初始化码，受本机文件权限保护；初始化成功后失效并删除。
- 设置管理员密码、密码确认和密码哈希持久化。
- 密码登录、登出、当前会话状态查询。
- 修改密码：验证当前密码，成功后撤销所有既有浏览器会话。
- 本机密码恢复命令；服务停止后执行，不删除用户文件、设置或审计数据。
- 登录限流、审计、Cookie 安全属性、CSRF/CSWSH 与 WebSocket Origin 防护。
- 独立可选的 Bearer API Token，和网页登录密码完全分离。
- 安全设置页、系统信息页，以及基础应用偏好。
- 持久化数据目录与运行期目录分离；重启后认证凭据和应用设置仍保留。
- 自动化测试覆盖初始化、登录、密码修改、恢复、重启和安全边界。

### 后续阶段（P1/P2）

- API Token 的网页创建、撤销和权限细分。
- 活跃会话列表及单会话撤销。
- 可变更的高级服务配置、变更预览、重启前校验和回滚。
- 审计日志网页检索、筛选与诊断包导出。
- 多用户、角色、外部身份提供商不属于当前规划，除非未来另行确认。

## 3. 认证状态与页面路由

系统必须明确区分以下状态：

| 状态 | 进入条件 | 允许访问 |
| --- | --- | --- |
| 未初始化 | 新安装且没有认证记录，也没有检测到损坏或无法读取的认证文件 | 静态资源、健康检查、初始化状态和初始化接口 |
| 未登录 | 已初始化，但请求没有有效会话或 Bearer Token | 登录页面、登录接口、健康检查和必要的公共资源 |
| 已登录 | Cookie 会话或有效 Bearer Token 通过验证 | 按现有统一认证策略访问受保护 API 与 WebSocket |
| 认证状态损坏 | 认证文件存在但无效、版本不支持或无法读取 | 不允许远程初始化；显示通用故障提示，并要求本机恢复 |

要求：

- 首次打开未初始化实例时显示初始化页，不显示文件管理、终端或仪表盘数据。
- 已初始化实例默认显示密码登录页，不要求用户名。
- 不允许通过删除浏览器 Cookie、访问隐藏 URL 或直接调用业务 API 绕过认证状态。
- 初始化完成后，所有初始化请求均返回冲突，不得重置已有密码。
- 认证文件损坏不得自动降级到未初始化状态；必须通过本机恢复流程处理。

## 4. 首次初始化流程

1. 服务启动时检查持久化认证记录。
2. 如果是新安装，生成一次性高熵初始化码，写入 `data-dir` 下的独立文件（权限 `0600`），并通过本机启动控制台输出一次。
3. 浏览器初始化页要求输入初始化码、新密码和确认密码。
4. 服务端验证初始化码、密码长度、确认值和限流规则。
5. 原子保存密码哈希与凭据版本，删除初始化码文件，并使初始化接口永久关闭，直到管理员执行本机恢复命令。
6. 初始化成功后进入登录页；不自动将初始化码当作登录凭据。

任何错误响应均不得回显初始化码、密码或密码哈希。

## 5. 登录、会话和密码修改

### 登录

- 请求：`POST /api/auth/login`，字段为 `password`。
- 成功：签发 `edgedesk_session` Cookie，并记录不含秘密的登录成功审计事件。
- 失败：统一返回认证失败，不区分“密码不存在”“密码错误”等敏感细节；按 IP 限流，默认每分钟 5 次。
- Cookie 属性：`HttpOnly`、`SameSite=Strict`、`Path=/`；HTTPS 部署必须启用 `Secure`。
- 默认会话 TTL 为 12 小时。服务进程重启后，既有 Cookie 会话失效。

### 修改密码

- 页面位于“系统设置 → 安全”。
- 输入当前密码、新密码、确认新密码。
- 成功后轮换会话签名密钥，使全部旧浏览器会话失效；当前浏览器也必须重新登录。
- 修改失败不得更改当前凭据；不得记录密码输入。
- 独立 Bearer Token 不因修改网页密码而自动变化。

### 本机恢复

- 目标命令：`edgedesk --reset-admin-password`。
- 必须要求服务已停止，并明确提示将重置管理员认证而非删除业务数据。
- 命令生成新的初始化码并将认证状态恢复为未初始化；保留 `settings.json`、审计日志和文件数据。
- 不提供公开网页重置接口。
- 命令未实现前，部署文档不得声称本机恢复功能可用。

## 6. 系统设置页面

设置页采用分组导航，首期至少包含：

### 安全

- 修改管理员密码。
- 显示当前会话是否有效及会话过期时间（如可安全获得）。
- 退出登录。
- 显示 API Token 认证是否已配置，但不得展示 Token 值。

### 系统信息

- EdgeDesk 版本和构建信息。
- 主机名、CPU 架构、内核版本、运行时间。
- 实际监听地址与端口。
- 文件 API 根目录、Bash 路径、审计日志状态及其他必要的有效配置摘要。
- 对敏感或可能泄露秘密的配置使用白名单，禁止返回密码哈希、Token、Cookie、初始化码、环境变量全集或完整命令行参数。

### 基础偏好

- 主题：浅色、深色、跟随系统。
- 默认文件视图：列表或网格。
- 隐藏文件默认显示状态。
- 终端字体大小。
- 仪表盘图表的显示时间窗口。

偏好必须进行类型、枚举和范围校验。需要跨浏览器共享的应用级设置存入带 schema 版本的 `settings.json`；纯浏览器布局状态可继续使用 `localStorage`。

### 高级配置（首期只读）

监听地址、端口、文件根目录、符号链接策略、上传上限、终端并发上限、终端空闲回收时间、指标采样周期和审计日志路径等先只读展示。后续若开放修改，必须逐项定义权限、持久化来源、生效时机、重启要求及失败回滚方式。

## 7. 持久化与部署要求

- 新增持久化 `--data-dir`；与运行期 `--state-dir` 分离。
- `data-dir` 默认路径必须持久且可写；系统服务部署应显式配置。禁止将认证记录和应用设置默认放入 `/tmp` 或 `XDG_RUNTIME_DIR`。
- `auth.json` 只保存哈希及版本化元数据；认证文件权限 `0600`，数据目录权限 `0700`。
- `settings.json` 使用 schema 版本和白名单字段。无效或不兼容设置应返回可诊断错误或安全回退默认值，不得破坏认证状态。
- 文件更新应使用临时文件、权限设置、必要的 `fsync` 和原子替换。
- 现有部署配置仍遵循“默认值 < 配置文件 < 环境变量 < 命令行”。网页设置不得静默覆盖部署级参数。
- 默认只监听回环地址；远程部署必须显式配置监听，并通过 TLS/VPN 或可信网关保护。

## 8. 目标 API

| 方法 | 路径 | 认证 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/auth/setup-status` | 公共 | 仅返回初始化是否完成 |
| `POST` | `/api/auth/setup` | 一次性初始化码 | 创建管理员密码 |
| `POST` | `/api/auth/login` | 公共、限流 | 密码登录并设置 Cookie |
| `POST` | `/api/auth/logout` | Cookie | 清除 Cookie |
| `GET` | `/api/auth/session` | Cookie 或 Bearer | 查询认证状态 |
| `POST` | `/api/auth/password` | Cookie | 修改密码并撤销旧会话 |
| `GET` | `/api/settings` | Cookie 或 Bearer | 读取允许访问的设置 |
| `PUT` | `/api/settings` | Cookie + 同源校验，或 Bearer | 更新白名单内的应用设置 |
| `GET` | `/api/system/info` | Cookie 或 Bearer | 返回筛选后的系统信息 |

所有接口继续使用统一 JSON 错误结构。Cookie 认证的非安全方法必须通过 Origin/CSRF 校验；WebSocket 握手必须执行认证和 Origin 校验。Bearer Token 仅用于直接 API 认证，不通过登录接口交换 Cookie。

## 9. 验收标准

1. 全新数据目录启动后，浏览器进入初始化页；未初始化时文件、终端、指标和设置 API 均不可访问。
2. 错误初始化码、过期/已用初始化码和限流场景均被拒绝；初始化成功后初始化码不可复用。
3. 密码以成熟算法的哈希形式保存；磁盘上和日志中均不存在明文密码。
4. 正确密码可以登录；错误密码返回通用认证失败；登录限流实际触发。
5. Cookie 具备规定的安全属性；异源写请求和异源 WebSocket 握手被拒绝。
6. 修改密码必须验证当前密码，成功后所有旧浏览器会话失效，独立 Bearer Token 行为不变。
7. 本机恢复命令要求服务停止，生成新初始化码；恢复前后的文件数据、设置和审计日志均保留。
8. 服务重启后管理员凭据和应用设置仍存在；进程重启使旧 Cookie 会话失效。
9. 认证文件损坏或不可读时失败关闭，不出现远程重新初始化绕过。
10. 系统信息接口不返回秘密；设置 API 拒绝未知字段、非法枚举和越界数值。
11. 配置文件、环境变量和命令行的优先级保持不变；网页设置不会覆盖部署级配置。
12. 更新 API 文档、部署文档、自动化测试与 `docs/testing.md`，如实记录未验证的目标平台。

## 10. 明确不做

- 多管理员、用户注册、角色与权限管理。
- OAuth/OIDC、邮件找回、短信找回或云端密码重置。
- 数据库或 ORM。
- 首期通过网页修改监听地址、文件根目录、Bash 路径等高风险部署参数。
- 将 CmdGuard 视为终端安全边界；Bash 实际权限仍由服务运行用户及操作系统隔离决定。
