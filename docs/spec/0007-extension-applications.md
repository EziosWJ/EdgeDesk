## 1. 目标与范围

EdgeDesk 在现有桌面、WindowManager、C++ HTTP 服务、认证、文件服务和终端能力之上增加可安装的扩展应用。首期只运行本地 ZIP 包中的静态 Web 应用；不执行应用自带的后端程序、Lua、JavaScript 服务端脚本或其他可执行包。manifest 可以预留后端和脚本运行时扩展点，但预留字段不得被解释为已具备执行能力。

扩展应用应支持安装、待审批、启用、禁用、升级、手动降级、卸载、版本保留、完整性检查、桌面启动和窗口恢复。应用可以使用受控宿主 API 访问文件、终端、系统能力和平台托管存储。应用间默认完全隔离，不提供应用间直接通信。

必须保留现有 EdgeDesk 业务功能与 V1.2 桌面交互。扩展应用接入现有 WindowManager，不另建窗口体系，不重写 FileService、PathSandbox、TerminalSessionManager、认证或指标采集。现有原生应用继续由现有 AppRegistry 注册和运行；本 SPEC 不要求把现有业务一次性迁移为扩展包。

### 1.1 与现有架构的关系

- 前端继续使用 React、TypeScript、Vite；设备端继续使用 C++17、libhv、GCC 15+ 和现有静态资源抽象。
- 扩展静态资源由现有 C++ HTTP 服务提供独立路由，与特权 API 路由严格隔离。
- WindowManager 是所有扩展应用窗口的统一管理者。
- 扩展管理元数据和应用 KV 数据使用独立的 SQLite 数据库；这是扩展平台的明确范围例外，不代表现有认证、设置、终端或指标模块改用数据库。
- 应用包、各修订版资源、用户数据和隔离保留数据存放在可配置数据根目录下，默认 /var/lib/edgedesk/apps，与可执行文件和内嵌资源分离。
- 开发 SDK、模板和 CLI 是独立开发工具，不嵌入 EdgeDesk 主程序。

## 2. 应用包、manifest 与版本身份

### 2.1 ZIP 包规范

ZIP 包必须包含 manifest.json、index.html 及其构建后的 JS、CSS、图片等静态资源。支持 React、Vue、Svelte 和原生 JavaScript，不限制开发框架。资源引用使用相对路径；SPA 客户端路由由静态资源服务回退至 index.html。首期不提供公共应用市场，也不要求数字签名。

安装界面由管理员主动上传 ZIP 包。平台必须检查 ZIP 结构、路径穿越、符号链接、重复文件名、非法路径、解压失败和磁盘空间。第 38 轮决定不设应用包固定大小上限或文件数量上限，按可用磁盘空间决定是否可安装；因此不得自行加入固定包体积或文件数量阈值。必须采用流式解压和临时目录，不把全部内容读入内存。不得将“没有固定上限”解释为可以忽略磁盘耗尽、重复路径、符号链接或压缩炸弹风险；相关残余风险见风险清单。

未签名包允许安装，但界面必须提示“发布者身份未经验证”。SHA-256 仅用于文件内容完整性校验，不证明发布者身份。

### 2.2 manifest

核心清单字段为稳定应用 ID、显示名称、SemVer 版本和入口。应用 ID 使用反向域名风格，例如 io.github.ezioswj.docker-manager；安装后不得随意改变。显示名称可以修改。入口首期为 index.html。

宿主 API 兼容模块要求 minHostApiVersion 和 maxHostApiVersion，二者均使用 SemVer，范围端点包含在兼容范围内。缺失、格式错误或不匹配时不得默认兼容，应用不得启用。核心 manifest 校验只负责核心必填字段；权限、窗口、网络和其他模块字段由对应模块解析和校验，不建立一个把所有扩展配置强行耦合的巨型解析器。

manifest 可声明：
- 功能模块权限，例如 files.manage、terminal.access；未获授权的模块能力默认拒绝。
- 外部网络来源白名单。
- 窗口默认尺寸、最小尺寸、单实例或多实例策略。
- 为未来后端和脚本运行时保留的扩展字段；首期必须拒绝或忽略执行这些运行时能力，不能执行任何包内后端或脚本运行时。

### 2.3 SemVer、内部修订与缓存

同一应用 ID 和 SemVer 可以由管理员确认后覆盖为不同内容。每次安装或覆盖必须生成唯一、不可变的内部 revisionId；对外仍显示应用声明的 SemVer。不同修订版具有独立的 SHA-256 文件清单、版本目录、回滚记录和静态资源 URL。

静态资源 URL 采用 /apps/{appId}/{version}/{revisionId}/ 形式。已发布的 revisionId 对应内容不可原地修改；覆盖同一 SemVer 时创建新修订，而不是复用旧 URL。资源可使用长期不可变缓存；应用安装状态、活动修订、授权状态等动态信息使用短缓存或禁止缓存。升级失败回滚到旧 revisionId，不回滚用户数据。

默认保留活动修订和最近两个历史修订；管理员可调整保留数量并手动保留指定修订。清理前必须检查活动版本、自动回滚目标、手动保留标记和其他引用。只删除应用代码与静态资源，不删除用户数据或审计记录。

## 3. 安装、启用、升级、降级与卸载

### 3.1 安装事务与恢复

安装流程必须具有明确状态机和幂等恢复规则：

1. 创建带操作 ID 的安装记录，包先进入临时目录。
2. 校验 ZIP 结构、manifest、路径、重复文件名、符号链接、可用磁盘空间和宿主 API 兼容性格式。
3. 流式解压并为每个文件计算 SHA-256，生成由平台维护的完整性清单。
4. 在同一数据根目录内将完整修订写入临时版本目录，完成必要的落盘和一致性检查。
5. 使用 SQLite 事务提交应用、修订、权限申请、完整性清单索引和操作状态；原子切换活动修订指针。
6. 任一步失败都不得暴露半成品活动版本。服务重启时根据 SQLite 状态和操作日志清理未完成临时操作、恢复一致状态；清理逻辑必须幂等。

首次安装即使包校验通过，也先进入待审批状态，不加入可启动应用列表。管理员完成首次权限审核后才可启用；拒绝时保持禁用，可重新审核或卸载。无签名包必须显示发布者身份未验证警告。

### 3.2 启用、禁用和权限变更

安装且启用的应用自动加入启动器。桌面图标和 Dock 固定由用户或管理员决定；快捷方式仅引用稳定 appId，不决定应用安装状态。禁用或卸载后必须同步更新应用列表。

禁用立即生效：阻止创建新窗口和新的宿主 API 调用，关闭应用所有窗口、关闭通信端口、取消事件订阅并释放实例临时资源；保留应用包、授权记录和用户数据。重新启用后重新执行兼容性和权限检查。

升级时保留原有授权。新增权限或权限范围扩大必须管理员审批；未批准的新权限继续拒绝。管理员单独修改或撤销某项权限时，现有运行实例继续使用创建时的权限快照；每次创建新运行实例时重新加载授权，包括首次启动、关闭后重开、刷新/重建 iframe 和桌面会话恢复。禁用应用与撤销单项权限不是同一操作：禁用立即终止运行实例，单项权限变更按上述快照策略延迟对现有实例生效。

### 3.3 升级、覆盖与降级

升级前检查包、manifest、宿主 API 兼容范围、完整性清单和新增权限。升级时通知并关闭应用所有窗口；新修订在临时目录完成校验后原子切换活动修订。失败时自动恢复旧修订，应用代码回滚不回滚用户数据。升级完成后由用户决定是否重新打开应用。

允许管理员确认后覆盖相同 SemVer；必须创建新的 revisionId，并分别维护资源 URL、缓存和 SHA-256 清单。允许管理员确认后主动降级到已安装或新上传的旧修订，原子切换并保留用户数据；界面明确提示安全与数据兼容风险。升级失败时的自动回滚不要求额外的降级确认。

### 3.4 卸载和数据处置

卸载前要求管理员明确选择保留或删除用户数据。选择保留时，数据进入隔离状态，不再被应用访问；同一 appId 重新安装时必须再次确认是否恢复。选择删除时清理该应用 KV 数据和用户数据。卸载立即撤销全部有效权限并删除有效授权记录；必要的审计历史必须保留，重新安装即使 appId 相同也必须重新审批授权。

## 4. 运行时、窗口与恢复

扩展应用在独立 iframe 沙箱中运行，必须不授予 allow-same-origin。首期允许脚本、表单提交、下载和弹窗能力；允许弹窗通过 allow-popups-to-escape-sandbox 等机制脱离沙箱，以兼容第三方登录。弹窗仍必须与 EdgeDesk 宿主和应用数据隔离，并限制危险导航及未经授权的宿主通信。允许标准 window.opener 与浏览器消息机制，但回调必须校验窗口引用、预期来源、随机 nonce、消息结构和回调状态。该策略存在无法完全消除的反向标签页劫持风险，见风险清单。

宿主先通过 postMessage 与指定 iframe 握手并校验随机会话令牌，再转移专属 MessagePort。后续 JSON-RPC 2.0 请求、响应和事件通过该端口通信。校验不能只依赖 origin；必须校验 iframe 窗口引用、握手令牌、消息结构、协议版本、request ID、方法命名空间、参数和运行会话状态。关闭窗口、禁用或升级时关闭端口并终止会话。应用之间默认禁止直接通信，也不得读取其他应用窗口、状态或存储。

每个运行实例有唯一 UUID，UUID 不是授权凭证。持久化的窗口记录与运行实例 UUID 分离；恢复窗口时创建新的运行实例 UUID，并重新取得权限快照。保存 appId、窗口位置、尺寸、最大化状态和焦点顺序；恢复时仅恢复仍已安装、已启用、宿主 API 兼容且授权有效的应用。完整接入现有 WindowManager，支持拖动、缩放、最大化、最小化、关闭和焦点切换。manifest 声明默认/最小尺寸和单/多实例策略。

关闭窗口即终止该运行实例，关闭 MessagePort、取消事件订阅，并关闭该实例创建的终端会话和其他临时资源；保留应用数据及已保存的窗口状态。首期静态 Web 应用不支持后台任务。应用运行时统一捕获未处理 JS 异常、Promise 拒绝、资源加载失败和宿主 API 错误；记录应用 ID、revisionId/版本、错误类型、时间及必要的脱敏堆栈，显示统一错误提示并提供重新加载，不采集业务数据或页面内容。

## 5. JSON-RPC 宿主 API、权限与事件

宿主 API 使用 JSON-RPC 2.0：request ID 关联请求和响应，方法使用命名空间，系统事件使用通知消息。协议必须定义版本、错误码、事件订阅、请求关联与超时处理。第 69 轮明确不设置协议级消息大小上限；文件传输的 1 MiB 分块限制不等于 JSON-RPC 总消息上限。第 62 轮明确不新增扩展应用级的调用速率、并发数和执行超时限制；现有 EdgeDesk HTTP/认证/CSRF/基础限流及现有服务资源边界不得因此删除。此选择存在资源耗尽风险。

宿主桥接层对每次 JSON-RPC 请求检查方法、参数、当前运行实例权限快照和会话状态。C++ 后端继续执行现有用户认证和 API 权限；首期不承诺 C++ 后端能在每条请求上识别扩展应用身份并执行应用级授权。所有特权 EdgeDesk API（文件、终端等）必须经宿主桥接调用，不向扩展开放 Origin:null 特权 API 直连路径。

首期权限按功能模块授权，例如 files.manage、terminal.access。文件操作仍按读取、写入、上传、下载、删除等方法分别校验操作类型并记录审计，但首期不提供每个文件动作单独的管理员授权开关。管理员授予 terminal.access 后，应用可创建终端会话、发送输入和读取输出，不逐次确认；只记录终端审计元数据，不记录原始输入输出。获得 files.manage 后，文件删除和覆盖无需逐次确认，相关操作必须审计。

平台提供应用隔离的 JSON 键值存储 API：get、set、delete、list，以及用于多键原子变更的 storage.transaction/批量操作。数据按 appId 隔离，SQLite 作为底层实现，扩展不得直接访问数据库。默认每应用最多 5 MiB，每键 JSON 值最多 256 KiB；超限写入返回明确错误且不得覆盖旧值；list 支持分页或结果数上限。浏览器 localStorage、IndexedDB 等不作为扩展应用受支持的持久化能力。

应用负责数据迁移：通过宿主存储 API 保存业务数据结构版本，在启动时执行迁移。EdgeDesk 不解析业务数据结构。迁移失败时保留原始数据并阻止应用正常启动，向管理员说明原因。迁移涉及的多键更新必须通过宿主原子事务 API，全部成功才提交，任一步失败整体回滚；事务不自动回滚事务外的文件操作。

宿主事件通过当前 MessagePort 实时推送，不持久化、不重放断连期间遗漏的事件。重新订阅后应用通过对应宿主 API 查询当前状态。首期不设置应用间通信机制。

## 6. 外部网络、弹窗与凭据

manifest 声明外部来源，默认拒绝未声明的目标，管理员审批后才允许。来源白名单对 API、图片、脚本、iframe 和表单等用途共用；宿主按 CSP 指令实施同一来源集合，不按用途分别审批。域名通配符 https://*.example.com 同时匹配根域名和所有子域名；协议、主机名和端口参与匹配。HTTP 和 HTTPS 两种协议均允许，具体目的地仍需符合已声明并获批的来源规则。

只校验外部请求初始 URL；初始请求通过后允许浏览器自动跟随重定向，不由 EdgeDesk 逐跳重新校验目标。浏览器本身的 CSP、CORS、混合内容和私有网络访问限制仍适用，但不能假设它们在所有请求类型上提供等价的保护。外部链接可以在应用 iframe 或弹窗中打开，并受来源白名单和 CSP 约束。

应用可读取有限的 EdgeDesk 登录状态信息；不得直接读取其他应用的数据。宿主 Cookie、Bearer Token 和内部认证秘密不得作为普通 JSON 键值数据或可重用明文凭据返回给未签名 iframe。确需复用宿主会话访问外部服务时，必须通过受控代理/授权流程，不得将原始宿主凭据交给应用。首期不提供专用秘密存储；需要安全保存 API Key、密码等秘密的应用，后续使用独立后端或专用凭据服务。

## 7. 文件 API 与传输

扩展应用使用虚拟路径，例如 /data/report.pdf；由现有 FileService/PathSandbox 解析到真实目录，不向应用暴露服务器绝对路径。应用访问范围不超过现有文件服务沙箱。manifest 的 files.manage 授权覆盖文件模块；宿主仍按读取、写入、上传、下载、删除等操作类型执行校验与审计。

应用层拒绝明显的 ../ 路径穿越并沿用现有文件服务符号链接规则。此决策不得削弱 ADR-0004 的 C++ PathSandbox：现有目录 FD、openat、符号链接边界、TOCTOU 防护和根目录约束继续作为实际安全边界，不能只依赖前端或字符串检查。

### 7.1 传输

大文件通过宿主桥接建立传输任务，使用专属 MessagePort 传输二进制分块，不使用 JSON Base64。固定每块 1 MiB，最后一块可以更小。严格顺序传输：每次只发送一个分块，宿主确认写入成功后再发送下一块；失败立即停止后续传输。普通文件传输只校验实际字节数与预期长度，不计算整文件或分块哈希；这不改变应用安装包 SHA-256 校验要求。

上传先写入与目标位于同一文件系统的临时文件。传输长度校验成功并确保数据已成功写入后，通过原子重命名/替换提交；提交前原文件保持不变，失败时保留原文件并清理临时文件。上传同名文件默认直接覆盖，无需逐次确认，但必须具备 files.manage 权限并写入审计日志。处理权限不足、磁盘空间不足、并发覆盖和提交失败。

传输失败、取消或运行实例终止时关闭文件句柄并删除临时文件；服务重启后清理未完成任务。不支持断点续传，重试必须从头开始且不得影响原目标文件。

### 7.2 文件锁与外部修改

所有经过 EdgeDesk 的文件操作使用同一服务端锁管理器。下载持有共享读锁，允许多个下载并行；上传、写入、覆盖和删除需要独占写锁。锁占用时立即返回 FILE_LOCKED，不排队、不等待。锁须覆盖成功、失败、取消、超时、异常释放和服务重启清理。

锁目标身份结合规范化路径与文件系统身份：已存在文件尽可能使用文件系统对象身份识别别名；目标不存在时使用规范化父目录身份与文件名。外部进程不受 EdgeDesk 内部锁约束；上传提交前尽可能检查目标文件是否已被外部替换或修改，发现冲突则终止提交并保留原文件，但元数据检查不能完全消除外部竞态。

### 7.3 目录列表

目录列表采用游标分页，宿主控制每页最大条目数，返回文件名、类型、大小和修改时间等必要元数据，不返回文件内容。游标由宿主生成并校验，不是授权凭证。尽可能检测目录变化，检测到变化返回 CURSOR_STALE，要求从第一页重新读取；不保存长期目录快照，也不承诺检测所有外部进程修改。

排序固定为目录优先、普通文件其次；每组内文件名升序、区分大小写、采用固定且不依赖系统区域设置的字符顺序。首期不开放自定义排序参数，游标按固定排序生成和校验。

## 8. 审计、完整性与异常

应用审计默认保留 90 天，管理员可配置保留期限，平台定期清理并记录清理结果和失败。审计日志与应用数据分开管理，卸载不删除历史审计，扩展应用不得自行删除日志，不记录终端原始输入输出。

终端审计记录应用 ID、操作者、会话 ID、创建/关闭时间、API 操作类型、结果和权限拒绝事件。文件审计记录应用 ID、实例 ID、操作者、操作类型、规范化目标路径、时间、执行结果及失败原因；不记录文件内容。审计日志访问受管理员权限控制。

安装时为每个应用文件计算 SHA-256 并保存每个 revisionId 的完整性清单。升级前校验新包，支持管理员手动完整性检查，不要求每次加载资源都重算哈希。检查发现哈希不一致时立即禁用并隔离异常修订，阻止继续加载、关闭全部窗口、撤销该运行修订的宿主 API 访问，保留异常文件供排查并记录审计。修复或重新安装后才能恢复。SHA-256 不能证明发布者身份，且非持续校验意味着未执行检查前不能保证实时发现篡改。

## 9. 非目标

- 首期不执行应用后端、Lua、Node.js 或其他脚本/服务端运行时。
- 不建设公共应用市场、签名发布者体系、应用间通信、秘密存储或后台任务运行时。
- 不把应用业务数据结构交给 C++ 核心解析。
- 不以扩展平台为由重写现有认证、文件沙箱、终端、指标、窗口管理或发布体系。
- 不把计划文档或模拟数据作为实现完成证据。

## 10. 验收标准

### 10.1 包与生命周期
1. 可从管理界面上传 ZIP；正确处理合法包、缺失 manifest/index、非法 JSON、重复路径、路径穿越、符号链接、损坏 ZIP、磁盘空间不足和解压失败。
2. 安装使用临时目录、SHA-256 清单、SQLite 事务和原子激活；进程在每个安装阶段崩溃后重启，均能幂等清理或恢复一致状态。
3. 未签名警告可见；首次审批前不能启动；拒绝权限后保持禁用。
4. 安装启用后出现在启动器；禁用、卸载后同步移除入口；桌面图标/Dock 固定项不会擅自改变应用安装状态。
5. 升级关闭全部应用窗口、临时验证后原子切换；故障自动回滚代码而不回滚用户数据；用户决定是否重开。
6. 相同 SemVer 不同内容必须生成不同 revisionId 和资源 URL；缓存与完整性清单不串版。
7. 降级必须管理员确认并提示风险；版本清理不删除活动、保留或回滚引用的修订。
8. 卸载明确选择保留/删除数据；保留数据隔离，重新安装恢复前二次确认；权限立即撤销，审计历史保留。

### 10.2 运行时与通信
9. iframe 未授予 allow-same-origin；脚本、表单、下载和弹窗能力符合本规范；宿主 API 不通过 Origin:null 直连开放。
10. 握手校验指定 iframe 窗口引用与随机会话令牌，再转移专属 MessagePort；伪造窗口、无效令牌、畸形 JSON-RPC、无效 request ID、未授权方法和过期会话均被拒绝。
11. 关闭窗口、禁用和升级均关闭端口、取消事件订阅并释放该实例终端会话和临时资源。
12. 每个新运行实例有新的 UUID 和权限快照；现有实例按既定快照运行。桌面恢复只恢复安装、启用、兼容且授权有效的应用。
13. 事件断连不重放；重新订阅后能通过状态 API 重新查询。
14. 应用 JS 异常、Promise 拒绝、资源加载失败和宿主 API 错误均有统一错误状态及脱敏审计记录，不采集业务数据或页面内容。
15. 应用间无法直接访问对方窗口、状态或存储。

### 10.3 权限、网络与存储
16. 未声明或未批准的权限默认拒绝；升级新增权限未审批时不能使用；禁用立即终止应用运行。
17. manifest 的 host API 范围按 SemVer 边界比较；缺失、格式错误或不兼容均拒绝启用。
18. 来源匹配覆盖协议、主机、端口；通配符按根域名及所有子域名规则处理；HTTP/HTTPS、初始 URL 校验和重定向行为与本规范一致，并记录对应风险。
19. KV 按 appId 隔离，5 MiB/应用、256 KiB/键；超限不覆盖旧值；事务批量写入全部提交或全部回滚；迁移失败保留数据并阻止启动。
20. 浏览器 localStorage/IndexedDB 不作为扩展应用受支持的持久化能力；秘密存储不在首期范围。

### 10.4 文件、审计与资源边界
21. 虚拟路径由现有 FileService/PathSandbox 处理，原有更强的目录 FD 和符号链接防护不得退化。
22. 目录游标分页、CURSOR_STALE、固定排序、大小写规则和元数据字段符合本规范。
23. 文件上传使用 1 MiB 顺序分块、逐块确认、长度校验、临时文件、原子替换和失败清理；同名默认覆盖。
24. 多下载可共享读锁；写操作独占锁；锁冲突立即返回 FILE_LOCKED；路径别名按文件系统身份尽可能统一；外部进程竞态按已接受边界处理。
25. 文件审计不记录文件内容；终端审计不记录原始输入输出；审计保留期限可配置，默认 90 天，清理结果可追溯。
26. 手动完整性检查发现篡改后自动禁用、隔离、关闭窗口、撤销运行访问并保留现场。
27. 扩展平台不得移除现有 EdgeDesk HTTP 请求体积限制、认证、CSRF/CSWSH、基础限流、终端会话上限、文件服务安全边界或资源清理机制。

### 10.5 工程交付
28. SDK、模板和 CLI 可独立安装使用；支持常见前端框架、manifest 校验、资源检查与 ZIP 打包。
29. 新增单元/集成测试覆盖状态机、权限、版本、SQLite 事务、路径、锁、传输中断和恢复。
30. 每个 Issue 有测试证据；行为代码修改执行 scripts/test-fast.sh，PR 执行 scripts/test-pr.sh；纯文档变更执行 Markdown/链接检查。
31. docs/README.md、相关 ADR、实施计划和 docs/testing.md 与实际实现状态一致；未实现功能不得标记为已实现。
