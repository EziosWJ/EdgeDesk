## 详细风险与实施约束

### R-01 未签名应用

管理员上传的 ZIP 没有密码学发布者身份。SHA-256 清单只能验证安装后的文件内容是否与清单一致，不能证明上传者是谁。首期不开放公共市场、不实现签名验证；安装界面必须显示发布者未验证。不得把“管理员上传”自动转换成“可信发布者”。

### R-02/R-19 包体积、文件数量和压缩炸弹

第 38 轮明确不设固定包大小或文件数量上限，因此不能私自添加固定阈值。仍必须检查 ZIP 结构、路径穿越、符号链接、重复文件名和磁盘可用空间。使用流式解压，禁止把所有文件内容或所有条目一次性读入内存。失败时删除临时操作；活动修订只有在完整校验后才可切换。此策略仍可能被高压缩比、超多小文件或低剩余空间利用，后续若需要固定配额，必须通过新的产品决策修改。

### R-03 无扩展级调用限流、并发和 JSON-RPC 消息上限

第 62 轮选择不设扩展应用级调用速率、并发数和执行超时限制；第 69 轮选择不设 JSON-RPC 协议级消息大小上限。不得在文档中宣称宿主对扩展调用有应用级资源配额。保留 EdgeDesk 已有 HTTP 请求体积限制、认证、CSRF/CSWSH、基础限流、终端会话上限和文件传输约束。JSON-RPC 解析失败、畸形消息和异常必须有明确错误处理，但这不能替代消息体积限制。此风险不应被隐藏。

### R-04 网络来源与重定向

所有外部用途共用一份获批来源白名单，HTTP/HTTPS 均可用，且只校验初始 URL。批准一个域名可能同时允许该域名的脚本、图片、iframe、表单和 API 请求；HTTP 可被中间人读取/篡改；重定向可能把浏览器带到初始白名单之外。CSP 必须正确配置，但不能承诺其对每种资源类型提供相同的逐跳目标校验。上线前需要使用真实目标浏览器验证实际行为，并在管理员授权界面清晰展示来源范围和 HTTP 风险。

### R-05 弹窗 opener

标准 window.opener 有助于第三方登录回调，但外部页面可能尝试导航 opener。回调必须验证预期来源、窗口引用、nonce、state 和消息结构；禁止在回调消息中接受任意宿主 API 指令或可重用宿主凭据。仅校验 origin 不足以完全解决反向标签页劫持。未来若安全等级要求更高，需要重新评估无 opener 的授权回调设计，并走决策变更。

### R-06/R-07 权限执行边界与延迟撤销

应用级权限由宿主桥接按实例权限快照执行，C++ 后端继续当前用户认证与 API 授权；首期不提供完整的后端 appId 级强制授权。特权 API 必须通过桥接，不能出现未经桥接的特权直连。单项权限撤销对当前实例延迟生效，因此管理 UI 必须区分“撤销权限（下次运行生效）”和“禁用应用（立即终止）”。任何应用禁用、升级、卸载和完整性异常都必须关闭端口和清理临时资源。

### R-08 文件路径安全

第 81 轮选择的“仅拒绝明显 ../”只描述扩展层额外策略，不得削弱现有 FileService/PathSandbox。当前 ADR-0004 定义了目录 FD、逐组件 openat、符号链接边界和 TOCTOU 防护；扩展必须复用这条路径，不能自行拼接服务器绝对路径。若当前实现与 ADR-0004 不一致，应先修复核心文件安全缺陷，而不是把弱检查推广给扩展。

### R-09 文件内容校验

普通文件上传/下载只检查预期长度与实际字节数，不计算内容哈希，因此不能发现同长度内容被篡改。临时文件和原子替换保证失败不会留下半成品，但不保证传输内容与源端逐字节相同。若未来需要端到端内容完整性，应通过新决策增加哈希校验。

### R-10 完整性检测

每个修订安装时生成 SHA-256 清单，升级前校验，并提供手动检查。发现不一致后必须立即隔离、禁用并审计；但由于不要求每次加载时重新计算，平台不能保证在人工检查之前实时发现磁盘篡改。该机制不是数字签名。

### R-11 秘密存储

应用 KV 只能存普通配置和业务状态。应用不得把 API Key、密码、Bearer Token 或宿主 Cookie 写入 KV 并声称受保护。宿主会话复用必须通过受控代理/授权机制；原始宿主凭据不能传入 iframe。专用秘密存储属于后续能力。

### R-12 数据迁移

迁移由应用作者编写，平台不理解业务 schema。迁移前后必须维护明确的数据结构版本；所有 KV 多键写入必须通过事务 API。迁移失败保留原始数据并阻止应用启动。事务之外的文件操作不属于 SQLite 回滚范围，应用开发者必须避免把跨资源迁移误认为全局原子操作。

### R-13 审计路径隐私

目标路径可能暴露业务目录、用户名或文件命名。审计不记录文件内容，但仍需要管理员访问控制、统一保留期限和可追溯的清理结果。审计事件不能由应用自行删除；卸载不删除历史审计。

### R-14 事件不重放

宿主通知是实时信号，不是持久化队列。连接断开期间事件会丢失；应用重新订阅后应查询当前状态，不得假设所有状态变化都已收到。

### R-15 内部修订

SemVer 是开发者声明的兼容/发布版本标签，不再唯一标识内容。所有管理界面、审计、缓存和回滚记录都要显示或关联内部 revisionId，避免把同 SemVer 不同内容误认为同一版本。

### R-16 SQLite 范围

SQLite 仅服务扩展应用元数据和 JSON KV。数据库文件必须存放在可配置数据根目录内，并保护文件系统权限。当前认证、设置、终端和指标实现不迁移；不能把本次决策解释为对现有无数据库架构的全面重写。

### R-18 会话复用

有限登录状态可向应用提供，但登录状态与可重用凭据必须分离。任何需要访问外部服务的会话复用必须明确授权目标、数据流和审计边界；没有安全代理实现时，不得用“把 Cookie/Token 传给 iframe”作为临时实现。

### R-20 外部文件修改

EdgeDesk 的内部读写锁无法约束通过 SSH、其他进程或管理员 shell 修改文件。上传提交前尽可能比较文件身份/元数据，检测到变化就中止；元数据相同不证明内容未变，因此该措施是风险降低，不是完全一致性保证。

## 发布门槛

- 所有风险条目都必须在实现 PR 的威胁模型和测试中被引用。
- 不得因为本清单登记了风险，就跳过 ZIP 结构校验、PathSandbox、认证、CSRF/CSWSH、审计脱敏或失败清理。
- 如果某项实现必须新增安全限制才能满足现有 EdgeDesk 核心安全基线，应优先保持核心防护，并记录与已确认产品选择的具体差异；不得静默削弱现有安全措施。
- 任何提高风险等级或改变已确认选择的措施，应通过新的 ADR/产品变更流程，而不是由编码 Agent 自行修改需求。
