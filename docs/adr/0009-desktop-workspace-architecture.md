# ADR-0009：桌面工作区与应用窗口管理架构

- 状态：**Accepted（V1.2.0 已实施）**
- 日期：2026-10-18
- 关联：[SPEC-0006 桌面工作区](../spec/0006-desktop-workspace.md)、[ADR-0001 技术栈](0001-technology-stack.md)、[ADR-0005 终端架构](0005-terminal-architecture.md)

## 背景

V1.1 已有 React 应用、可拖拽/缩放的浮动窗口、终端会话、文件管理和设备仪表盘，但主业务页仍通过 App.tsx 的 active 页面状态切换，WindowLayer 只负责部分终端、编辑器和预览窗口。V1.2 需要将主要业务应用统一纳入桌面窗口模型，同时保留既有业务能力与后端协议。

## 决策

### 1. 保留既有技术栈

- 保留 React + TypeScript + Vite、xterm.js 和当前图标体系。
- 保留 C++17/libhv 后端、REST/WebSocket API、认证和业务服务；桌面化主要是前端架构改造。
- 不引入 Electron/Tauri，不引入完整桌面环境框架，不为窗口管理新增第三方依赖。
- 窗口拖拽与缩放继续使用自研实现，并补齐组件生命周期、边界约束、焦点和层级行为。

### 2. 建立桌面层与应用注册表

建议职责边界：

| 模块 | 责任 |
| --- | --- |
| DesktopShell | 桌面背景、图标网格、Dock、启动器、全局桌面快捷键 |
| AppRegistry | 应用元数据、入口、图标、说明、实例策略和默认尺寸 |
| WindowManager | 对外提供统一窗口操作 API，执行单/多实例策略和窗口状态转换 |
| WindowStore | 保存当前运行期窗口实例及几何/状态数据，提供稳定订阅 |
| WindowLayer | 根据 WindowStore 渲染窗口；最小化时隐藏但不卸载组件 |
| DesktopPersistence | 本地布局的 schema、校验、序列化、恢复和迁移/回退 |

具体文件名可随现有目录结构调整，但职责边界必须保持。业务应用不得直接管理全局 z-index 或修改其他窗口状态。

### 3. 应用实例策略

- 设备概览和系统设置为单实例应用。
- 文件管理为多实例应用，每个窗口独立维护当前目录。
- 终端工作区可多实例；现有多 Tab 和每 Tab 独立 Bash 会话必须保留。文件管理中按当前目录启动的终端仍可作为独立终端窗口存在。
- 编辑器和预览作为窗口类型继续复用现有组件，不强制作为桌面快捷方式。
- 应用 ID 稳定且与显示名称分离；持久化数据不依赖组件类名或数组下标。

### 4. 窗口生命周期

- 窗口关闭、窗口最小化、WebSocket 断连和 Bash 会话结束是不同事件。
- 最小化不卸载业务组件；关闭终端窗口只分离 UI，不隐式终止后端 Bash。
- 显式结束终端会话仍由终端 UI 发起并遵守既有服务端会话授权和回收规则。
- 窗口状态转换集中在 WindowManager/WindowStore；应用组件只负责自身业务状态。
- 恢复时所有窗口几何数据都必须通过当前视口约束和 schema 校验。

### 5. 响应式策略

桌面优先。窄屏时自动最大化应用窗口，保留核心操作；不在 V1.2 实现完整移动端多窗口交互。断点由 CSS/布局实现决定，初始建议 768 CSS px，并以实际目视验收为准。

## 影响

### 正面影响

- 业务页面通过 AppRegistry 统一启动，后续新增运维应用不需要再修改主导航分支。
- 桌面交互与业务组件分离，窗口行为可以独立测试。
- 复用已有窗口与终端能力，控制改造范围。

### 成本与风险

- App.tsx、WindowLayer 和 windowStore 需要重构，必须分阶段迁移，避免一次性重写。
- 最小化从卸载改为隐藏后，需要确认终端订阅、编辑器状态和资源释放行为正确。
- 应用实例策略、窗口恢复和会话重连必须有自动化测试，不能仅凭视觉检查。

## 备选方案

1. 继续使用侧边导航，只优化视觉：不能满足完整桌面模式的已确认需求。
2. 引入 react-rnd 或完整桌面组件框架：现有窗口交互已具备基础能力，新增依赖会带来适配、许可证和跨架构前端构建维护成本；V1.2 不采用。
3. 重写业务组件：重复实现现有功能，风险与成本均高；不采用。

## 验收

- 主要应用统一由 AppRegistry/WindowManager 打开，不再依赖 active 页面切换作为主导航。
- 窗口生命周期和终端会话生命周期解耦。
- 窗口状态转换、单/多实例规则、最小化保持挂载和几何约束均有测试。
- 不新增后端 API、数据库、桌面框架依赖或运行时依赖。
