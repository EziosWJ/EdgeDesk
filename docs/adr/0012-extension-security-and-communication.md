# ADR-0012：扩展应用权限、通信与网络安全边界

- 状态：**Accepted with documented risks（决策已确认，残余风险见风险清单）**
- 日期：2026-10-18
- 关联：[SPEC-0007](../spec/0007-extension-applications.md)、[ADR-0002 架构与安全](0002-architecture-security.md)、[ADR-0004 文件沙箱](0004-path-sandbox.md)、[ADR-0008 认证与设置](0008-authentication-and-settings.md)

## 背景

扩展应用包由管理员上传，但首期不验证数字签名。静态 Web 代码需要调用文件、终端和存储等特权能力，同时允许访问经管理员批准的外部网络来源。安全边界必须明确区分浏览器 iframe 隔离、宿主桥接权限、现有 C++ API 认证和管理员对应用的信任。

## 决策

### 1. 权限模型与授权生命周期

- manifest 声明功能模块权限，默认拒绝；首期授权单位为功能模块，例如 files.manage、terminal.access。
- 第 17 轮要求文件 API 按读取、写入、上传、下载、删除等操作类型校验。第 40 轮随后选择模块级授权以简化管理。实现采用模块级管理员授权，并在每个文件方法上校验操作类型和记录审计；首期不提供每个文件动作独立的授权开关。
- 首次安装包校验成功后进入待审批状态，未完成管理员首次权限审核不得启动。
- 升级保留原授权；新增权限或范围扩大需管理员审批，未批准的新能力继续拒绝。
- 单项权限变更对已运行实例延迟生效：当前实例继续使用创建时的权限快照；首次启动、重开、刷新/重建 iframe 和桌面恢复均创建新实例并刷新快照。
- 禁用应用是不同的操作：立即阻止新窗口和宿主 API 调用，关闭所有窗口、端口与事件订阅，保留包、授权记录和数据。卸载立即撤销所有有效授权并删除有效授权记录，保留必要审计历史；重装必须重新审批。
- 宿主桥接层对每次请求检查方法、参数、实例状态与实例权限快照。C++ 后端继续现有用户认证和 API 权限；首期不声称 C++ 后端在每条请求路径上都能识别 appId 并实施扩展应用级授权。
- 特权 EdgeDesk API 必须通过 JSON-RPC 宿主桥接；不为沙箱 iframe 开放 Origin:null 特权直连路径。现有认证、CSRF/CSWSH、HTTP 请求体积限制、基础限流和服务端权限不得移除。
- 第 14 轮的通用“操作确认”原则受后续具体决策限定：terminal.access 授权后，终端创建/输入/输出不逐次确认；files.manage 授权后，文件删除和覆盖不逐次确认。不得为这两类操作额外添加逐次确认弹窗。其他 API 的确认行为须按具体方法契约定义，不得假设全部操作都需要或都不需要确认。

### 2. JSON-RPC 与 MessageChannel

- JSON-RPC 2.0 使用 request ID 关联请求/响应，方法使用命名空间，系统事件使用通知；协议定义版本、错误码、事件订阅和超时处理。
- 宿主先通过 postMessage 与指定 iframe 握手，校验 iframe 窗口引用、随机会话令牌和消息结构，再转移专属 MessagePort。
- 端口建立后，消息通过专属 MessagePort 传输。每次请求仍校验方法、参数、权限快照和会话状态；端口存在本身不是授权凭证。
- 关闭窗口、禁用或升级时关闭端口并使会话失效；旧实例消息不能复用到新实例。
- 第 19 轮要求协议具有消息大小限制，第 69 轮后续明确选择不设置协议级消息大小上限。以第 69 轮为准：不得自行引入 JSON-RPC 总消息大小阈值。文件分块 1 MiB 仅限制文件传输块，不限制其他 JSON-RPC 消息。
- 第 19 轮要求超时语义，第 62 轮明确不设置平台级 API 执行超时。协议/SDK 可以定义调用方等待超时和错误返回，但等待超时不能被描述为后端操作必然已取消；平台不实施扩展应用级执行超时、速率或并发配额。

### 3. iframe、弹窗与外部页面

- iframe 使用独立沙箱且不授予 allow-same-origin；首期允许脚本、表单、下载和弹窗。
- 允许使用 allow-popups-to-escape-sandbox 等机制让外部弹窗脱离沙箱，但弹窗不得获得宿主 DOM、宿主凭据或应用 KV 的访问权。
- 标准 window.opener 通信被允许。回调必须验证窗口引用、预期来源、随机 nonce、消息结构和回调状态。仅验证 event.origin 不足以证明消息可信。
- opener 的跨源窗口仍可能尝试导航 opener；在保留标准 opener 的前提下，浏览器不能保证彻底消除此风险。该残余风险必须显示在风险清单中，不能以“已校验 postMessage”声称完全防护。

### 4. 网络来源与 CSP

- manifest 声明外部来源，默认拒绝未声明目标，管理员审批后生效。
- 所有外部用途共用同一来源白名单，包括 API、图片、脚本、iframe 和表单提交。CSP 仍须设置相应指令，但不按用途分别申请域名。
- 域名通配符例如 https://*.example.com 同时匹配根域名 example.com 和所有子域名；匹配必须考虑协议、主机和端口。通配符不能匹配任意域名。
- HTTP 和 HTTPS 均允许；目标来源仍须声明并获批。明文 HTTP 可能被窃听或篡改。
- EdgeDesk 只校验初始 URL；初始请求通过后允许浏览器自动跟随重定向，不由宿主逐跳重新校验目标。浏览器 CSP/CORS/混合内容/私有网络限制仍可能影响请求，但不能视为所有请求类型的等价逐跳授权控制。
- 共用白名单意味着获批域名可能提供远程脚本；来源批准不等于代码经过审计，也不意味着该站点可信。

### 5. 宿主登录状态与秘密

- 可向扩展提供有限的宿主登录状态信息；确需复用宿主会话访问外部服务时，必须经受控代理或显式授权流程。
- 不向未签名 iframe 返回原始宿主 Cookie、Bearer Token、会话签名材料或其他可重用秘密。
- 首期不提供秘密存储。普通 JSON KV 不得用于保存 API Key、密码或令牌；需要秘密管理的应用须等待独立后端或专用凭据服务。
- 宿主登录状态信息应只包含业务必需字段，不暴露不必要的系统身份或账户细节。

### 6. 审计、完整性与资源风险

- 审计默认保留 90 天，管理员可配置，平台定期清理并记录清理成功/失败。卸载应用不删除历史审计；应用不得自行删除日志。
- 终端审计只记录应用 ID、操作者、会话 ID、创建/关闭时间、API 操作类型、执行结果和权限拒绝，不记录原始终端输入输出。
- 文件审计记录应用 ID、实例 ID、操作者、操作类型、规范化目标路径、时间、结果及失败原因，不记录文件内容；访问日志受管理员权限控制。
- 安装时逐文件计算 SHA-256；升级前校验新包；支持手动完整性检查，不要求每次资源加载重算。检测到不一致时立即隔离修订、禁用、关闭窗口、撤销运行访问、保留现场并审计。
- SHA-256 只能检测内容变化，不能证明发布者身份；手动检查不是持续监控。
- 不新增扩展应用级 API 调用速率、并发数或执行超时限制；不设置 JSON-RPC 消息大小上限。现有 EdgeDesk 核心防护不因此取消。残余资源耗尽风险列入风险清单。

## 与既有决策的冲突处理

1. 第 26 轮曾允许扩展直接调用现有 API；第 27 轮明确特权 API 通过桥接，按第 27 轮实施。
2. 第 19 轮提到消息大小限制；第 69 轮明确取消协议级大小上限，按第 69 轮实施。
3. 第 17 轮的文件操作类型校验与第 40 轮模块级授权合并为：模块级管理员授权 + 方法级操作校验/审计，不提供首期独立动作授权开关。
4. 第 14 轮的一般操作确认受第 15 轮终端行为和第 79 轮文件删除/覆盖行为限定。
5. 第 30 轮核心 manifest 最小字段与第 64 轮宿主 API 兼容声明合并为：核心字段由核心校验器检查，API 兼容模块将 minHostApiVersion/maxHostApiVersion 作为启用前必需字段。
6. 第 38 轮不设包大小/文件数固定上限，不取消第 20 轮 ZIP 结构、路径穿越、符号链接、重复文件名和压缩风险检查；只取消固定数值阈值，改为流式解压与可用磁盘空间检查。

## 后果

- 运行时边界与权限生命周期明确，但应用级权限主要由宿主桥接执行；若出现可绕过桥接的特权 API 路径，将构成安全缺陷。
- 接受的风险包括未签名代码、宽泛网络用途白名单、HTTP、重定向目标不逐跳校验、opener、无应用级限流及无 JSON-RPC 消息大小上限。风险登记与后续治理见 docs/security/extension-app-risk-register.md。
- 本 ADR 不表示上述能力已经实现。实现前必须完成威胁建模、测试和安全审查。
