# ADR-0013：扩展文件 API、分块传输与并发一致性

- 状态：**Accepted（需求已确认；实现尚未开始）**
- 日期：2026-10-18
- 关联：[SPEC-0007](../spec/0007-extension-applications.md)、[SPEC-0002 文件管理](../spec/0002-file-management.md)、[ADR-0004 文件路径沙箱](0004-path-sandbox.md)、[ADR-0002 架构与安全](0002-architecture-security.md)

## 背景

扩展应用需要通过宿主 API 访问 EdgeDesk 已有文件服务。传输必须适配 MessagePort 和静态 iframe，同时保证原子替换、锁冲突、审计、路径隔离及失败清理。首期不实现文件断点续传。

## 决策

### 1. 路径与授权

- 扩展 API 使用虚拟路径，例如 /data/report.pdf；不向应用返回服务器绝对路径。
- 文件模块使用 files.manage 管理员授权。每个文件 API 仍按读取、写入、上传、下载、删除等操作类型校验参数、执行结果和审计。
- 应用层拒绝明显的 ../ 路径穿越，符号链接沿用当前 FileService/PathSandbox 的既有规则。
- 不得弱化 ADR-0004 的 PathSandbox：所有操作继续通过统一 FileService、目录 FD 与逐组件 openat 解析，保持既有符号链接边界和 TOCTOU 防护。前端桥接层和字符串检查不是文件系统安全边界。
- 扩展应用可以访问现有文件服务沙箱允许的目录，不扩大 --file-root 范围。
- 目录列表只返回名称、类型、大小、修改时间等元数据，不返回文件内容。

### 2. 目录列表分页与排序

- 使用宿主生成并校验的游标分页，限制每页条目数；游标不是授权凭证。
- 尽可能检测目录内容变化；检测到变化时返回 CURSOR_STALE，要求应用重新从第一页读取。无长期目录快照，也不承诺检测所有外部进程修改。
- 排序固定为目录优先、普通文件其次；各组内按名称升序、区分大小写，比较顺序不依赖系统区域设置。首期不提供自定义排序参数。
- 若底层文件名不能按约定的显示编码表示，接口必须采用确定且无歧义的编码/错误处理，不能静默合并不同文件名。

### 3. 传输协议

- 大文件传输由宿主桥接创建传输任务，使用专属 MessagePort 发送二进制数据，不用 JSON Base64。
- 每个分块固定 1 MiB，末块可更小。严格顺序传输，一次仅允许一个分块在途；宿主确认写入成功后才发送下一块。
- 分块传输有明确的任务 ID、方向、预期总长度、偏移/序号、确认、结束和取消状态。实例 UUID 不是授权凭证；任务 ID 也不能替代会话权限校验。
- 普通文件传输仅比较实际字节数与预期长度，不计算分块或整文件 SHA-256。该规则不适用于应用 ZIP 安装包；应用包仍须逐文件 SHA-256。
- 不支持断点续传。取消、失败、运行实例终止或服务重启后关闭文件句柄、清理临时文件和未完成任务；重新上传从头开始。

### 4. 上传提交

- 上传写入同一目标文件系统内的临时文件，不直接截断/覆盖目标文件。
- 完成后核对实际长度与预期长度，并确保数据已成功写入；然后以同一文件系统内的原子重命名/替换提交。
- 提交前原目标文件保持不变；校验或提交失败时保留原文件并清理临时文件。
- 同名目标默认直接覆盖，不要求逐次确认；仍须 files.manage 授权并记录审计。
- 必须处理磁盘空间不足、权限不足、写入失败、fsync/rename 失败和并发覆盖。原子替换的原子性不能证明内容正确，也不能自动检测所有外部进程修改。

### 5. 服务端锁

- 所有经过 EdgeDesk 的文件读写、上传、下载、覆盖和删除都通过同一服务端锁管理器。
- 下载持有共享读锁；多个下载可并行。上传、写入、覆盖和删除持有独占写锁。
- 锁竞争立即返回 FILE_LOCKED，不排队、不等待。SDK 可提供重试建议，但平台不自动重试。
- 锁必须在成功、失败、取消、异常、超时和服务重启路径释放或清理；操作终止时不得遗留永久锁。
- 锁身份结合规范化路径与文件系统对象身份：现有文件尽可能使用文件系统对象身份识别别名；目标不存在时使用规范化父目录身份和文件名组合。
- 锁只协调经过 EdgeDesk 的操作。提交前尽可能检测目标文件是否被外部替换/修改；发现冲突则终止并保留原文件。不能声称该检查完全消除外部竞态。

### 6. 审计

每个文件操作记录应用 ID、实例 ID、操作者、操作类型、规范化目标路径、时间、执行结果及失败原因。不得记录文件内容。审计日志由平台管理，管理员可按权限查看，遵守默认 90 天且可配置的保留与清理策略。应用不能自行删除审计记录，卸载不删除历史日志。

## 实现注意事项

- 不得在 libhv 事件循环上执行无界阻塞文件 I/O；复用现有异步/有界执行模式和 RAII FD 管理。
- 文件锁不能取代 PathSandbox，也不能代替认证、授权、请求体积限制或现有文件服务错误映射。
- 新扩展传输协议应使用独立命名空间和错误码，避免改变现有 HTTP 文件 API 的既有语义。
- 第 81 轮只限定扩展层额外的路径检查，并没有授权削弱现有 FileService 的更强防护。若代码现状与 ADR-0004 不一致，必须先补齐现有安全边界并测试，不能为迁就扩展而降低安全性。
