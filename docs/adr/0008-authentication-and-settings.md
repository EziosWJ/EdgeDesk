# ADR-0008：V1.1 管理员密码认证、首次初始化与系统设置

- 状态：**Implemented（V1.1.0，2026-10-17）**
- 日期：2026-10-17
- 关联：[V1.0 认证契约 ADR-0003](0003-v1-auth-api-protocol.md)、[产品范围](../spec/0001-product-scope.md)、[SPEC-0005](../spec/0005-authentication-and-settings.md)、[配置与部署](../config.md)

> 本 ADR 记录 V1.1 的已实现设计。实际行为以 [API 文档](../api.md)、[配置文档](../config.md) 和 [验证矩阵](../testing.md) 为准；V1.0 的历史契约见 ADR-0003。

## 背景

V1.0 使用部署级访问 Token 换取签名会话 Cookie。产品已确认，面向浏览器的主认证方式应调整为单管理员密码：新安装首次打开进入初始化，创建管理员密码；后续使用密码登录，并可在系统设置中修改密码。自动化客户端仍可使用独立的 Bearer Token。

EdgeDesk 必须继续保持单二进制、无数据库、适用于边缘 Linux 的轻量部署方式，并支持只读根文件系统及独立的可写数据目录。

## 决策

### 1. 管理员模型

- V1.1 采用**单管理员、仅密码登录**；不要求用户名，不引入多用户、角色、OIDC 或 OAuth。
- 网页登录密码与 API Bearer Token 是两种独立凭据，禁止互相替代。
- 所有文件、终端、系统和设置 API，以及 WebSocket，继续受统一认证与 Origin/CSRF 校验保护；只开放健康检查、初始化状态、初始化和登录等必要公共端点。

### 2. 首次初始化

- 新安装在持久化数据目录中没有有效认证记录时进入未初始化状态；此时只能访问静态登录/初始化界面、健康检查和初始化相关端点，不得访问文件、终端、指标或设置数据。
- 初始化接口只要求设置管理员密码和确认密码，不再要求本机初始化码。接口必须限流；已初始化时重复调用返回冲突，不得覆盖已有凭据。
- 简化取舍：未初始化实例的首次访问者可以直接设置管理员密码。默认监听回环地址；远程部署必须在初始化完成前限制访问，并置于 TLS/VPN 或可信网关之后。
- 如果认证文件存在但格式错误、版本不支持或无法读取，必须**失败关闭**并要求本机修复；不能将损坏状态自动解释为新安装，否则可能绕过登录保护。

### 3. 密码存储与策略

- 仅保存经成熟密码哈希实现计算的哈希及所需参数，绝不保存明文密码、可逆加密密码或将普通 SHA-256 直接作为密码哈希。
- 首选经过维护、可在目标工具链上验证的 Argon2id 实现；不得自行实现密码哈希算法。若目标平台无法支持，应在实现前提交兼容方案，不得静默降级到弱方案。
- 每个密码使用独立随机盐，哈希记录必须包含算法与参数版本，以便未来升级。
- 最小密码长度为 6 个字符；允许长密码和空格，不强制大小写、数字、符号组合，也不强制定期更换。
- 登录失败继续采用按 IP 限流，默认每分钟最多 5 次，并写入不含密码、Token 或 Cookie 的审计事件。

### 4. 登录会话与密码修改

- 密码验证成功后签发 `edgedesk_session` Cookie，使用 `HttpOnly; SameSite=Strict; Path=/`；HTTPS 部署必须通过 `--cookie-secure` 设置 `Secure`。
- 默认会话有效期为 12 小时，继续支持部署级 `--session-ttl` 配置。会话签名密钥使用安全随机数生成，服务进程重启后会话失效。
- 修改密码必须验证当前密码、新密码和确认密码。成功后轮换会话签名密钥，使所有既有浏览器会话失效，并要求重新登录。
- 修改管理员密码不应隐式修改或撤销独立配置的 API Bearer Token。
- 继续保留 V1.0 的 CSRF/CSWSH 防护、WebSocket Origin 校验、请求限流和审计要求。

### 5. 本机密码恢复

- 提供本机命令行恢复流程：`edgedesk --reset-admin-password`，使用数据目录 `.lock` 的非阻塞 `flock` 证明服务已停止。
- 恢复操作只重置认证状态；不删除文件数据、审计日志或应用设置。
- 恢复完成后重新启动服务，通过初始化页面设置新密码。禁止提供无需认证的网页密码重置接口。

### 6. 可选 API Token

- 保留现有 `--auth-token-file`、`EDGEDESK_AUTH_TOKEN` 和调试用途的 `--auth-token`，作为可选的 Bearer API 凭据。
- 配置了 Token 的自动化客户端可继续通过 `Authorization: Bearer <token>` 调用受保护 API；未配置 Token 时，Bearer 认证不可用，但管理员仍可使用密码登录网页。
- Token 不再作为网页登录密码，也不再通过 `POST /api/auth/login` 换取浏览器 Cookie。
- V1.1 已取消“非回环监听必须配置 Token”的限制：远程浏览器访问以管理员密码认证为基础，API Token 保持可选；非回环监听仍必须显式配置，并在部署文档中强调 TLS/VPN。

### 7. 持久化边界

- 新增持久化数据目录配置 `--data-dir`，与现有运行期目录 `--state-dir` 分离。`state-dir` 可用于运行期文件与审计日志；认证状态和应用设置必须存放在重启后仍保留的 `data-dir`。
- 认证文件为 `auth.json`，包含 schema 版本、密码哈希、哈希参数和凭据版本，不含明文密码。
- 应用设置文件为带 schema 版本的 `settings.json`，只保存明确列入白名单的应用设置。部署级配置（监听地址、文件根目录、Bash 路径、上传上限等）仍由配置文件、环境变量和命令行控制，V1.1 设置页不直接覆盖这些来源。
- 文件写入采用临时文件、权限设置、必要的 `fsync` 和原子替换；目录权限建议 `0700`，认证文件权限 `0600`。
- 默认数据目录应落在持久化且可写的位置；系统服务部署必须明确指定合适的数据目录。不得将认证数据默认放在可能被系统清理的 `/tmp` 或 `XDG_RUNTIME_DIR` 下。

### 8. 系统设置范围

V1.1 分阶段实现：

1. **安全设置：** 修改管理员密码、查看当前会话状态、退出登录。
2. **系统信息：** 展示版本、架构、内核、运行时间、监听配置及有限的有效配置摘要；必须使用白名单，禁止暴露密码哈希、Token、Cookie 和其他秘密。
3. **基础偏好：** 主题、默认文件视图、隐藏文件偏好、终端字体大小和仪表盘显示窗口等。浏览器局部状态可使用 `localStorage`；需要跨浏览器共享的应用级设置才写入 `settings.json`。
4. **高级运维设置：** 文件根目录、监听地址、上传上限、终端资源限制等首期只读展示，后续逐项评估是否开放修改，并明确生效时机及重启要求。

### 9. API 方向

V1.1 目标 API（最终响应格式遵循现有统一错误契约）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/auth/setup-status` | 只返回是否已完成初始化，不返回任何秘密 |
| `POST` | `/api/auth/setup` | 创建管理员密码（未初始化时，限流） |
| `POST` | `/api/auth/login` | 使用密码登录并签发 Cookie |
| `POST` | `/api/auth/logout` | 清除当前 Cookie |
| `GET` | `/api/auth/session` | 查询当前认证状态 |
| `POST` | `/api/auth/password` | 验证当前密码并修改密码 |
| `GET` | `/api/settings` | 读取允许展示的设置与偏好 |
| `PUT` | `/api/settings` | 保存白名单内的应用设置 |
| `GET` | `/api/system/info` | 获取经过白名单筛选的系统信息 |

旧版 `POST /api/auth/login { "token": "..." }` 契约已由密码登录取代。脚本客户端直接使用 Bearer Token，不依赖 Cookie 登录交换。

## 影响与迁移

- V1.1 已按本 ADR 更新代码、API 文档、部署文档、前端和测试矩阵；V1.0 的旧 Token 登录契约仅保留在 ADR-0003 作为历史记录。
- 升级后如果没有有效的持久化管理员凭据，系统进入未初始化流程，首次访问者直接设置管理员密码；现有 API Token 不会被自动转换为管理员密码。
- 需要在目标 x86_64、ARM64 及计划支持的 musl 工具链上验证密码哈希依赖、持久化目录权限和重启行为。
- 不引入数据库或 ORM；不实现多用户、角色管理、远程密码找回、OAuth/OIDC 或云端控制平面。
