# ADR-0001：技术栈与编译基线

- 状态：**Accepted（已确认）**，其中明确标为候选的事项尚未定案
- 日期：2026-10-16
- 关联：[产品范围](../spec/0001-product-scope.md)

## 背景

EdgeDesk 是嵌入式／边缘 Linux 设备上的轻量 Web 运维工具，重点是单二进制部署、资源占用可控以及文件管理、Bash 终端和设备监控。正式构建需要兼顾 ARM 和 x86 平台。

## 决策

| 项目 | 决策 | 状态 |
| --- | --- | --- |
| 核心语言 | C++17 | 已确认 |
| HTTP/WebSocket 网络层 | libhv | 已确认 |
| Linux 编译器 | GCC 15+ | 已确认 |
| Linux C 库/链接 | musl 静态链接，发行目标优先 static-pie（可用性按工具链验证） | 已确认方向 |
| 前端资源嵌入 | GCC 的 `#embed` 扩展，将构建后的静态文件编入可执行文件 | 已确认 |
| Linux 架构 | x86_64、ARM32、ARM64 各自构建 | 已确认 |
| 数据库 / ORM | V1.0 均不引入 | 已确认 |
| 前端 UI | React | 候选，待确认 |
| 浏览器终端 | xterm.js | 建议，待确认 |
| 构建系统 | CMake + Ninja | 建议，待确认 |
| OpenHarmony ARM64 | 作为可能的独立平台适配 | 待验证／待确认 |

## 使用 `#embed` 的边界

- 保持业务源代码以 C++17 为基线；允许针对 GCC 15+ 使用 `#embed` 扩展，**不表示全面采用 C++26**。
- `#embed` 是编译阶段能力，**不会要求设备端升级 musl 或内核**；设备端仍需满足 ELF、CPU ABI、内核及运行权限条件。
- ARM32 / ARM64 必须分别使用具有对应目标支持的 GCC 15+ 交叉编译工具链及 musl sysroot。
- 资源须由构建过程生成路径索引；不能仅通过一个 `#embed` 声明自动完成多文件路由。
- 对非 GCC 15+ 或不支持该扩展的平台，可保留 `objcopy` / `.incbin` 备选，但**是否实现回退尚未确认**。
- React 只作为前端候选；如选用，Node 构建工具仅存在于开发/CI 环境，目标设备不需要 Node。
- TLS、终端与静态打包均需要在各目标平台实际验证，不能以宿主机编译通过替代运行验收。

## 影响

- 编译器版本固定会提高旧工具链迁移成本，但资源嵌入实现更直接。
- 不采用数据库/ORM，设备历史数据和复杂用户体系不属于 V1.0 的既定范围。
- 使用单独的构建产物及工具链配置适配不同架构，不承诺“一份 ELF 通用所有平台”。

## 非决策

本 ADR 不指定 React UI 组件库、具体日志库、TLS 实现或 OpenHarmony 兼容层，这些留待后续确认。
