# ADR-0011：扩展应用包、运行时与数据存储

- 状态：**Accepted（基于 Grill 第 1～13、20～24、28～39、41～47、49、53～61、64～68、74～78 轮决策）**
- 日期：2026-10-18
- 关联：[SPEC-0007](../spec/0007-extension-applications.md)、[ADR-0001 技术栈](0001-technology-stack.md)、[ADR-0009 桌面架构](0009-desktop-workspace-architecture.md)、[ADR-0010 桌面持久化](0010-desktop-persistence-and-recovery.md)

## 背景

EdgeDesk V1.2 已有原生应用注册表、统一 WindowManager、C++ HTTP 服务、文件与终端 API。扩展应用需要独立分发、升级和卸载，同时不能把任意第三方代码直接加载到宿主 DOM 权限域，也不能要求设备额外安装 Node、Python 或 Java 运行时。

## 决策

### 1. 首期仅支持静态 Web 包

- 应用以 ZIP 分发，必须含 manifest.json、index.html 和构建后静态资源。
- 支持 React、Vue、Svelte、原生 JS 等开发框架；资源使用相对路径，支持 SPA 回退。
- 首期只运行静态 Web 资源。manifest 可以预留后端/脚本运行时扩展点，但不执行包内后端、Lua、Node.js 或其他服务端代码。
- 无公共应用市场；不实现数字签名。未签名应用需明确显示发布者身份未验证。
- 应用开发 SDK、模板和 CLI 独立于主程序，负责 manifest 校验、资源检查、常见前端模板与 ZIP 打包。

### 2. 独立沙箱与宿主通信

- 每个应用由独立 iframe 加载，禁止授予 allow-same-origin。
- 首期允许脚本、表单、下载和弹窗；允许弹窗脱离 iframe 沙箱以兼容第三方登录，但限制危险导航和宿主通信。
- 通过 postMessage 对指定 iframe 握手，校验窗口引用、随机会话令牌和消息结构，再转移专属 MessagePort。
- 后续 JSON-RPC 2.0 请求、响应和事件使用专属端口；关闭窗口、禁用或升级时关闭端口。
- 每条宿主请求检查方法、参数、协议版本、请求 ID、会话状态和运行实例的权限快照。应用间不提供直接通信。
- 标准 window.opener 通信允许用于弹窗回调；回调验证窗口引用、预期来源、随机 nonce、消息结构和回调状态。此决定无法彻底消除恶意外部页面导航 opener 的风险，详见风险清单。

### 3. C++ 静态资源服务与不可变修订

- 复用现有 C++ HTTP 服务新增独立静态资源路由，与特权 API 路由隔离。
- 每个应用版本内容有内部 revisionId；静态 URL 为 /apps/{appId}/{version}/{revisionId}/。同一 SemVer 覆盖产生新 revisionId，不覆盖既有修订内容。
- 服务负责 MIME、SPA 回退、应用专属 CSP 和缓存控制。修订资源长期不可变缓存；安装状态、活动修订和授权等动态状态短缓存或禁止缓存。
- 应用包、修订文件和用户数据存于可配置数据根目录，默认 /var/lib/edgedesk/apps；与可执行文件和内嵌资源分离。

### 4. SQLite 的范围限定

- 使用 SQLite 保存应用清单索引、安装状态、活动修订、权限申请/有效授权、操作状态与审计索引。
- 应用 JSON KV 与应用管理元数据共用 SQLite 数据库，按 appId 和键名隔离；扩展应用只能经宿主 API 访问，不得直接打开数据库。
- 这是一项仅适用于扩展平台的范围例外，不要求现有认证、设置、终端和指标模块改用 SQLite，也不改变 V1.2 现有实现状态。
- 数据库状态变更使用事务；应用包与用户数据仍位于文件系统。

### 5. 安装与修订生命周期

- 安装包先进入临时目录，流式校验和解压，为每个文件计算 SHA-256，形成平台维护的完整性清单。
- 通过 SQLite 操作状态和事务提交安装阶段；完成验证后原子激活修订。启动时清理未完成临时操作，恢复规则幂等。
- 首次安装须先完成管理员权限审核，审批前不可启动。
- 升级关闭应用全部窗口，在临时目录校验后原子切换活动修订；失败自动恢复旧修订，用户数据不回滚。升级成功后由用户决定是否重开。
- 管理员确认后可主动降级；升级新增权限必须重新审批。
- 默认保留活动修订和最近两个历史修订；可调整保留数量、手动固定修订。清理前检查活动版本和回滚/保留引用。
- 安装时建立每文件 SHA-256 清单，升级前校验，支持手动检查。发现哈希不一致时禁用并隔离异常修订、关闭窗口、撤销其运行访问、保留现场并记录审计。

### 6. 窗口与运行实例

- 扩展应用完整接入现有 WindowManager，支持拖动、缩放、最大化、最小化、关闭和焦点切换。
- manifest 声明默认/最小尺寸和单/多实例策略。
- 持久化窗口记录与运行实例 UUID 分离。每次新建运行实例生成新的 UUID，UUID 不作为凭据。
- 自动恢复上次桌面会话时，只恢复已安装、已启用、兼容且授权有效的应用；每个新运行实例重新取得权限快照。
- 单项权限撤销不改变已有运行实例的快照；禁用应用则立即关闭全部窗口、端口和事件订阅。
- 关闭窗口即终止该运行实例及其创建的终端会话和临时资源；首期不支持后台任务。

### 7. 应用存储与迁移

- 提供 get、set、delete、list 和事务型批量写入 API；每应用默认 5 MiB，每键 JSON 值默认 256 KiB。
- 超限写入返回明确错误且不得覆盖旧值；list 必须分页或限制结果数。
- 浏览器 localStorage、IndexedDB 不作为受支持的持久化契约。敏感凭据不使用普通 KV 存储；首期无专用秘密存储。
- 应用自行保存业务数据结构版本并执行迁移。多键迁移通过宿主 SQLite 事务全成全败；迁移失败保留原数据并阻止应用正常启动。
- 卸载时管理员明确选择保留或删除数据。保留数据进入隔离状态，重装恢复须再次确认；卸载立即撤销有效授权，但不删除审计历史。

## 后果与取舍

- 该设计允许独立交付和升级前端应用，同时避免把动态后端执行引入首期设备运行时。
- SQLite 是扩展平台的局部新依赖；需要明确数据库文件权限、备份/恢复、迁移和损坏恢复策略。
- 未签名 ZIP 与人工上传使管理员成为首期信任边界；SHA-256 只提供内容完整性，不证明来源。
- 不设置包大小/文件数固定上限、JSON-RPC 消息大小上限或扩展 API 调用限流，是已确认的风险选择，必须在风险清单中持续可见。
- 本 ADR 不声称扩展运行时已实现；实现状态以代码和测试为准。
